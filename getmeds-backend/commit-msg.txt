require a proof of payment on the order form, or a reason there is none

The MedRep attaches the deposit slip while creating the order, which is where
they already look for it. This replaces the "Attach File(s) to Sales Order"
control that used to sit in that spot and discard whatever was dropped on it -
`// UI-only for now - files are listed here but never uploaded anywhere` - so it
looked like filing and was not. A rep would have believed their slip was on
file.

Submit stays locked until there is either a file or a reason, so Finance never
opens an order and finds a blank where the evidence should be. The reason is a
four-value enum rather than free text, for what the division field taught on
Sep 2: terms, on terms and w/ terms are three answers to one question and
nothing downstream can count them. Other requires a note.

The upload runs AFTER create returns, because the storage path is
orders/<id>/... and there is no id until then. It is deliberately not allowed to
fail the mutation - the order is already in Zoho by that point, and reporting
failure for an order that exists is worse than a missing file the rep can attach
from the order's Proof of Payment tab. A second toast says so when it happens.

The requirement is a gate on the FORM, not on POST /api/orders, which still
accepts an order with neither and has a test saying so. A server-side
requirement would reject every order that is about to get a proof.

Needs orders.no_payment_proof_reason and no_payment_proof_note, applied to
Supabase by hand before deploying since create now inserts them.
